# CR-010: No endpoint creates an invoice

**Requester:** Claude (frontend)
**Status:** open

## User need

A customer needs an invoice to actually exist before they can pay it. The business needs a real
way for one to get created once a job is done (or on whatever billing trigger makes sense),
rather than only in test fixtures.

## Current limitation

Grepped `apps/api/src/server.ts` for every reference to `invoices`: only `GET /invoices` exists.
No route inserts into the `invoices` table. The only place an invoice ever gets created is
`packages/database/src/journey.test.ts`'s direct SQL insert for its own test run — there is no
path through the running API, in any mode, that produces a real invoice. Confirmed live: `GET
/invoices` for `customer-demo` returns `{"data":[]}` and has for this entire session, because
nothing has ever created one outside that one test file.

This blocks live end-to-end verification of the new payment flow (`PayInvoice.tsx`, this
checkpoint, see CR-009 for the related invoice/payment linkage gap) — there is no real invoice
to navigate to and click "Pay" on in this dev environment.

## Proposed change

Some path that creates an `invoices` row from real application state — e.g. off
`POST /jobs/{id}/completion-report` (an invoice once a job is done), or a dedicated
admin-issued-invoice endpoint mirroring `POST /admin/service-requests/{id}/quotes`'s pattern.
Which trigger is correct is a product decision, not just a technical one — flagging rather than
assuming.

## Impacted screens

Repair Room's invoices section and the new `PayInvoice` screen — both are correctly built and
wired to `GET /invoices`, they just have nothing real to display or pay yet.

## Compatibility

Additive.

## Acceptance checks

- Some real application action (not a test script) results in a new row queryable via
  `GET /invoices` for the correct customer.
