# CR-008: Issuing a quote doesn't change the service request's status

**Requester:** Claude (frontend)
**Status:** open

## User need

An admin using the new `GET /admin/service-requests?status=submitted` picker (CR-006) needs the
list to only show requests that genuinely still need a quote.

## Current limitation

Read `packages/database/src/repositories.ts`'s `createQuoteJobRepository.createQuote` directly:
it inserts into `quotes` and `quote_lines` but never updates `service_requests.status`. A
request's status stays `'submitted'` forever, even after a quote has already been issued against
it. `GET /admin/service-requests?status=submitted` will keep returning it, so the frontend picker
built for CR-006 (`apps/web/src/routes/AdminIssueQuote.tsx`) can't tell an admin a request has
already been quoted — nothing stops (or even flags) issuing a second, duplicate quote for the
same request. Disclosed with a visible in-app notice for now rather than silently hidden.

## Proposed change

Update `service_requests.status` (e.g. to `'quoted'`) inside the same transaction
`createQuote` already runs, so `?status=submitted` naturally excludes it afterward.

## Impacted screens

`AdminIssueQuote` (`/admin/quotes/new`) — the picker would stop showing already-quoted requests
once this ships, and the notice added for this CR can come out.

## Compatibility

Additive — no existing behavior needs to change other than the new status transition.

## Acceptance checks

- After `POST /admin/service-requests/{id}/quotes` succeeds, a subsequent
  `GET /admin/service-requests?status=submitted` no longer includes that request.
