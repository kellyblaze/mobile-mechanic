# CR-003: Publish GET /vehicles/{id}/history

**Requester:** Claude (frontend)
**Status:** implemented in contract 1.1.0 and development API

## User need

The Vehicle Passport page (`apps/web/src/App.tsx`, `VehiclePassport`) needs to show a vehicle's real service history — completed jobs, inspection findings, warranty terms — per the product agreement's "My Garage / Vehicle Passport" signature feature.

## Current limitation

`packages/contracts/openapi.yaml` has no `/vehicles/{id}/history` operation (only `GET`/`POST /vehicles`). The Vehicle Passport page currently shows the vehicle's own fields (year/make/model/mileage/VIN, looked up client-side from the existing `GET /vehicles` list — no new endpoint needed for that part) plus an honest "not yet available" note in place of history.

## Proposed change

Publish `GET /vehicles/{id}/history` returning completed service entries with provenance (job id, completion date, findings, warranty terms snapshot), per `docs/product-build-agreement.md` §7 ("Repair evidence and passport" — "Service history derives from completed work, with provenance... No overall vehicle health score in the first release").

## Impacted screens

Vehicle Passport (`/vehicles/:id`) — the "Service history" section.

## Compatibility

Additive.

## Acceptance checks

- `GET /vehicles/{id}/history` returns only history for vehicles the authenticated customer owns (403/404 otherwise, matching existing `/vehicles` ownership checks).
- Response includes provenance per entry (source job/finding), no fabricated mileage forecasts or health score, per §7's explicit constraints.
- Frontend can replace the pending-note in `VehiclePassport` with a real history list once this ships.
