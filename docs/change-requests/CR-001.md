# CR-001: Generated API client is missing mutation methods

**Requester:** Claude (frontend)
**Status:** implemented in contract 1.1.0; frontend adapter cleanup remains

## User need

The Repair Room and vehicle-creation screens need to submit `POST /api/v1/vehicles` and `POST /api/v1/quotes/{id}/accept`, both of which are already defined in `packages/contracts/openapi.yaml`.

## Current limitation

`packages/contracts/generated/client.ts` only exports a `get<T>(path)` method. There is no `post`, no header support (e.g. `Idempotency-Key`, `X-Dev-User-Id`, `X-Dev-Role`), and no per-operation typed methods (`createVehicle`, `acceptQuote`) despite `operationId`s being defined in the contract.

## Proposed change

Regenerate `packages/contracts/generated/client.ts` (via `packages/contracts/scripts/generate-client.ts`) to emit, per `operationId`:
- A typed method per operation (`getSession`, `listServiceCatalog`, `listVehicles`, `createVehicle`, `getJob`, `acceptQuote`), each returning the documented response schema.
- Support for `POST`/other verbs, request bodies, and required headers (`Idempotency-Key` per `VersionedCommand` operations).
- A pluggable header provider (so the frontend can attach `X-Dev-User-Id`/`X-Dev-Role` in development and swap to cookie-based session auth later without regenerating).
- Typed error responses using the `ApiError` schema on non-2xx.

## Impacted screens

- Vehicle creation (My Garage / vehicle intake)
- Quote review & acceptance (Repair Room)
- Any future mutation once its contract operation is published (change orders, booking, messages)

## Compatibility

Additive — no existing `get()` behavior needs to change; this only adds methods.

## Interim workaround (documented, not silent)

Until this lands, `apps/web/src/lib/apiAdapter.ts` implements `createVehicle` and `acceptQuote` with a direct `fetch` call against the exact path/method/headers/schema defined in `openapi.yaml`, isolated in that one file, clearly commented as a stopgap pointing at this CR. It does not invent any endpoint, field, or status value beyond what the contract already declares.

## Acceptance checks

- `createApiClient(...).createVehicle(input)` performs `POST /api/v1/vehicles` and returns the typed `Vehicle` on 201, throws typed `ApiError` otherwise.
- `createApiClient(...).acceptQuote(id, { expectedVersion, idempotencyKey })` sends the `Idempotency-Key` header and returns the accepted quote or a typed 409/422 error.
- Frontend adapter's interim `fetch`-based methods can be deleted with no behavior change once the generated methods exist.
