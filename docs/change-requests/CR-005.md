# CR-005: Publish service-request submission and upload endpoints

**Requester:** Claude (frontend)
**Status:** implemented and fully wired — `Intake` performs real photo uploads to private storage
(the storage bucket, missing in this dev environment, was created 2026-09-11). The one remaining
gap is that uploaded photos aren't linked to the service request they were added to — see
[CR-017](CR-017.md).

## User need

The "Tap Your Trouble" guided intake flow (product agreement's signature intake experience) needs to actually submit a customer's vehicle + symptoms + photos as a service request, and needs somewhere to send the photos.

## Current limitation

`packages/contracts/openapi.yaml` has no `/service-requests` or `/uploads` operations (both are named in `docs/product-build-agreement.md` §8 as planned endpoint families, not yet defined). `apps/web/src/App.tsx`'s new `Intake` component is a real, fully interactive 4-step wizard (vehicle → symptoms/notes → photos → review) — vehicle selection uses the existing `GET /vehicles`, and photos are genuinely previewed client-side via `URL.createObjectURL` — but the final "Submit request" button is genuinely `disabled` (not just styled inert) and nothing is ever sent over the network for photos or the submission itself.

## Proposed change

- `POST /uploads`: authorized upload initiation/finalization per §8, returning an attachment reference usable by a subsequent service-request submission.
- `POST /service-requests`: accepts vehicle id, category, selected symptoms, free-text notes, and attachment references from `/uploads`; returns a request id and routes to a priced service, diagnostic appointment, or bodywork consultation per the product agreement's intake description.

## Impacted screens

The Intake wizard (`/intake/:category`) — the photo step and the final Submit action.

## Compatibility

Additive.

## Acceptance checks

- `POST /service-requests` enforces the same customer/vehicle-ownership checks as `POST /vehicles`.
- `POST /uploads` constrains file type/size and produces authorized, non-public references, per §7 ("Repair evidence and passport").
- Frontend can wire the existing disabled Submit button and photo previews to real calls with no other layout changes once both ship.
