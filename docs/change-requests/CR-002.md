# CR-002: Job resource should expose its linked quote id and version

**Requester:** Claude (frontend)
**Status:** implemented and frontend cleanup verified

## User need

The Repair Room needs to let a customer approve the quote attached to their job, and show a real, current price when a version conflict happens.

## Former limitation

`GET /jobs/{id}` (`packages/contracts/openapi.yaml`) returns no quote reference, and there is no `GET /quotes/{id}` operation at all. The frontend (`apps/web/src/App.tsx`) currently hard-codes `quoteId: 'quote-1'` and `expectedVersion: 1` to match the backend's seeded fixture (`packages/domain/src/state.ts`) — real, not invented, values for this checkpoint, but not something the client can generalize beyond one demo job, and there is no way to recover after a 409 (no endpoint to fetch the current version from).

## Implemented change

- Add a `quote` (or `quoteId`/`quoteVersion`) field to the `Job` schema returned by `GET /jobs/{id}`.
- Publish `GET /quotes/{id}` so the client can refetch the current version after a 409 and actually resolve the conflict instead of only reporting it.

## Impacted screens

Repair Room quote approval.

## Compatibility

Additive.

## Acceptance checks

- `GET /jobs/{id}` response includes the linked quote's id and current version when one exists.
- `GET /quotes/{id}` returns the current quote (403/404 enforced per the same ownership rules as job/vehicle reads).
- Frontend can remove the hard-coded `quote-1`/`expectedVersion: 1` in `apps/web/src/App.tsx` once this ships.

The generated client and frontend now use the published job quote linkage and quote lookup; no
hard-coded quote id/version remains in the live Repair Room flow.
