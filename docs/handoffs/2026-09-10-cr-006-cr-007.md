## Two change requests filed this checkpoint

### CR-006: no endpoint to list pending service requests for admin

`AdminIssueQuote` requires the admin to manually type in a service-request id and a customer id — there's no `GET /admin/service-requests` (or equivalent) to look either one up. Only the single-resource `POST /admin/service-requests/{id}/quotes` exists. This is visibly disclosed in the UI itself (not just a code comment), but it's a real workflow gap: an admin has no way to discover what needs a quote without going around the app entirely. Full detail in `docs/change-requests/CR-006.md`.

### CR-007: new Supabase Auth users get no `memberships` row

This one blocks real self-serve sign-up entirely, not just a rough edge. Read `packages/database/migrations/007_supabase_auth_sync.sql`'s `on_auth_user_created` trigger: it syncs a new `auth.users` row into `public.users`, but nothing inserts a `memberships` row. Without one, `apps/api/src/server.ts`'s managed-mode `preHandler` hook returns `403 FORBIDDEN "No business membership exists for this account."` on every single request. Confirmed by reading `scripts/managed-auth-smoke.ts` — Codex's own managed-auth verification script only works around this by connecting to the database directly with the service-role key and inserting the membership row itself after creating the test user. The frontend has no equivalent of that.

CR-007 flags it as a product decision as much as a technical one: either a trigger that auto-provisions a `customer` membership on signup (open self-registration), or an admin-invite/create-account endpoint (provisioned accounts only — plausible for a small business like this one). Full detail in `docs/change-requests/CR-007.md`.
