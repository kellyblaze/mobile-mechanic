## Two real bugs found and fixed this checkpoint — both mine, both frontend

### Bug 1: confirming a booking hold returned a genuine 500

Root cause: `apps/web/src/lib/apiAdapter.ts`'s `request()` helper always sent `Content-Type: application/json`, even for `confirmBookingHold`/`refundPayment`, which send no request body. Fastify's strict JSON body parser rejects an empty body when that header is present (`FST_ERR_CTP_EMPTY_JSON_BODY`) — confirmed by reading the actual server log line, not guessed. Fixed by only setting the header when a body is actually present, with a regression test asserting it's absent on a no-body call.

### Bug 2: paying a real invoice returned a 422

Root cause: the live API returns `invoice.totalMinor` as a JSON string (e.g. `"12000"`), not a number, despite the `Invoice` type declaring it `number`. Division and display already tolerated this via JavaScript's loose numeric coercion, but `JSON.stringify` does not — sending it straight through in the payment request body silently became a string, which the server's `z.number()` check on `amountMinor` correctly rejected. Fixed with `Number(invoice.totalMinor)` at the one call site that re-serializes it, and documented the quirk directly on the `Invoice` type for whoever touches it next.

Both are entirely frontend fixes (`apps/web/**`) — nothing here needed a Codex change, but flagging them since they're real defects that would have shipped otherwise.

## New change request filed this checkpoint

### CR-013: `GET /mechanics` returns duplicate rows and isn't scoped to a business

Confirmed live via curl: `GET /mechanics` for `customer-demo` returned the same mechanic four times. The query (`createBookingRepository.listMechanics`) has no `DISTINCT` and no `business_id` filter at all — in a real multi-tenant deployment this would leak other businesses' mechanics into the picker, not just show duplicates. `Booking.tsx` deduplicates by id client-side in the meantime; that workaround doesn't address the cross-tenant scoping gap. Full detail in `docs/change-requests/CR-013.md`.
